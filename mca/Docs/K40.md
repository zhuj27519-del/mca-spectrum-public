# Measuring the K-40 line

Run the three commands in the root README for a working synthetic example. Replace the synthetic inputs with measured files and their own metadata for a laboratory run. Remove the demo marker for measured data.

## Inputs

Use the repository CSV header `channel,cumulative_count`. Set `channels` to the native number of bins. Provide either calibrated bin centers in `energy_keV` or independent `energy_points` bracketing the peak and sidebands. Supply a measured or preselected resolution `fwhm_keV` at 1460.8 keV. The sample alone produces a gross line screen. For a background-corrected result, add the independent blank with verified live times in seconds. For Bq/kg, add the standard's certificate value, both masses in kg and confirmation that the reference response applies. All three runs must share energy mapping, resolution, detector and geometry, with comparable filling and attenuation.

The peak window spans ±1 FWHM. Sidebands span 2–3 FWHM on each side. The software subtracts a local linear continuum for each spectrum. The line maximum must lie within half a FWHM of 1460.8 keV, and the peak excess must exceed the approximate five-sigma threshold. A sample and blank can both contain K-40. The sample must also exceed the blank after live-time normalization. Nearby interfering lines, low counts, gain drift and uncertain resolution require a separate assessment. The threshold is an exploratory screen. It has no measured false-positive rate or formal detection limit.

With background-corrected ROI count rates R, sample mass m and reference concentration A, the estimate is

```
sample_Bq_kg = standard_Bq_kg * (standard_mass_kg / sample_mass_kg)
                              * (sample_net_cps / standard_net_cps)
```

The reported one-sigma uncertainty propagates counting statistics including the shared blank. The certificate, masses, efficiency transfer, drift, self-attenuation and spectral interferences require their own uncertainty estimates. Missing standard information leaves the activity field null. A weak sample can also give a null result.

## Reproducing the public data checks

1. Download the [OpenGamma K-40 interactive export at the pinned revision](https://raw.githubusercontent.com/OpenGammaProject/Gamma-Spectrum-Database/60d3382af94f3db69775de0f7795dbd21386c768/assets/spectra/K-40.html) as `K-40.html`. Run `python ai/quantification/check_public_k40.py --open-gamma-html K-40.html`. The export contains a background trace and a signed clean trace. Their sum reconstructs the plotted gross spectrum. On this 8192-bin HPGe example, assuming 3 keV FWHM, the smoothed maximum is 1460.59 keV and the background trace alone falls below the screen. Source masses and reference activity for this acquisition are unavailable here.
2. The same command reproduces the K mass percentages from measured peak rates, background measurements, sample masses and sample-specific sensitivities in [Hoeling, Reed and Siegel, Tables I and II](https://www.siegelsoft.com/reprints/ajp_67_440_2.pdf). It also runs without the HTML argument. Across four samples the maximum absolute difference from the paper's reported estimates is 0.011 percentage points. This checks the arithmetic against the same published experiment. Derived K-40 activities assume natural isotopic composition and 313 Bq/kg per percent K, following [IAEA-TECDOC-1363, Table 2.5](https://www-pub.iaea.org/mtcd/publications/pdf/te_1363_web.pdf).
3. For the [eight-sample LaBr3 workbook](https://doi.org/10.17632/n6yfhrz824.1), install the existing quantification dependencies and run `python ai/quantification/k40_benchmark.py workbook.xlsx --fwhm-kev WIDTH > folds.csv`. Replace WIDTH with the independently measured resolution for that instrument. The command verifies the same workbook hash as the original regression. Each fold fits a linear response and intercept to the other seven samples using their masses, reference activities and live-time-normalized peak areas. It reports every held-out prediction, signed error, and the overall MAE, retaining negative estimates for unbiased error accounting. This empirical benchmark is separate from the matched-standard CLI. The real workbook was unavailable in this development run. No eight-sample score is claimed for this method.
